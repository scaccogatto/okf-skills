Contribute

Bug reports, questions and pull requests are welcome. Here is how the project is run, so you know what to expect.

How the project is run

  • okf-skills is an independent community project. It is not part of the OKF project and is not affiliated with the authors of the spec.
  • It is maintained and sponsored by ekar.is. The code is MIT licensed, copyright ekar.is and the okf-skills contributors. There is no contributor license agreement.
  • Decisions about direction are discussed in GitHub issues. Once made, they are recorded as decision concepts in .okf/decisions/, in OKF, so you can read why things are the way they are.
  • The vendored copy of the spec in skills/okf/reference/SPEC.md is never edited here. It is copied verbatim from upstream.

A good issue

  • Says which part you used: the validator, the visualizer, a skill, the hook, the MCP server or the Action, and which version.
  • Includes the smallest bundle or input that shows the problem. A single concept file is often enough.
  • Says what you expected, what happened, and quotes the output.
  • If you ran the skills in an agent other than Claude Code, says which one. We have not tested other agents, so these reports are especially useful.

A good pull request

  • Changes one thing, and says why in the description.
  • Comes with a test when it changes behaviour. The tests are plain Python scripts in tests/, run with make test.
  • Passes make lint and make validate locally.
  • Merged work keeps its author: we merge your commits or add Co-authored-by, and name you in the changelog.

You do not need to bump the version, write the changelog entry or update the .okf/ bundle. The maintainers do that before merging. Your part is the code, the tests and a clear description. The local commands are in CONTRIBUTING.md.

Questions about the format itself

If your question or proposal is about OKF, not about these tools, open it in the OKF repository. We follow the spec. We do not extend it here, except with x- keys as the spec allows. If you are not sure which side a problem is on, open it here and we will help sort it out.

Code of conduct

We follow the Contributor Covenant, version 2.1, as our code of conduct. It applies to issues, pull requests and anywhere else someone speaks for the project. If something goes wrong, write to chat@ekar.is. Reports stay confidential.

Security issues

Please do not open a public issue for a vulnerability. Report it privately through GitHub, as SECURITY.md describes. Include the affected part, the version, and a minimal input that reproduces it. Only the latest release receives fixes.
