Upgrading to OKF v0.3

OKF v0.3 mostly makes the v0.2 text more precise. Two changes alter how a reader interprets an existing v0.2 bundle. This page explains both, what our --migrate flag does about them, and the separate rename of the okf-skills plugin.

What changed in the spec

The full list is in §13 of the spec. The two breaking changes, in plain words:

1. A bare path is relative to its own file

In v0.3, a path field without a leading / is read from the folder of the file that contains it, the same way a Markdown link is. Some v0.2 examples wrote bare paths meaning "from the bundle root". Those now point somewhere else.

The spec allows a fallback: for a bundle that declares okf_version 0.2 or older, or no version, a reader may try the bundle root when the relative path does not resolve (§12.1). Our tools use that fallback and warn about each path that needed it.

2. Only current verifications count

A verified entry now counts towards the trust tier only if it is at or after generated.at. A concept that a person reviewed and an agent later rewrote is no longer human-reviewed. Nothing needs rewriting for this: some concepts just show a lower tier until someone checks them again. The spec notes that the tier can only go down, which is the safe direction.

Among the smaller changes: date-only timestamps such as "2026-06-30" are valid again and mean the start of that day in UTC, a date-time needs an offset, the root index.md can carry title, description and license, and keys starting with x- are reserved for extensions. superseded_by is new.

What --migrate does

--migrate rewrites a v0.1 or v0.2 bundle in place, then validates it. It is the only mode of the validator that writes files, so commit or back up the bundle first and read the diff afterwards.

uv run skills/validate/scripts/okf_validate.py .okf --migrate

It edits the text, not a re-serialized copy: comments, key order, quoting, line endings and a byte order mark are kept. Running it twice changes nothing the second time. On concepts it:

  • adds a leading / to block-style path fields that only resolve from the bundle root (in a bundle that declares 0.2 or older, or no version),
  • moves a v0.1 timestamp into generated, with the actor process:okf-migrate, because the original author cannot be recovered,
  • moves a v0.1 # Citations list into sources.

In the root index.md it renames our old upkeep and recursive keys (see below), and sets okf_version: "0.3", but only once no root-only path is left anywhere in the bundle.

What it refuses

After each rewrite it parses the file again and compares. If the result differs from the original in anything other than the intended change, it leaves the file alone and warns, naming the file. It also skips path values with leading or trailing spaces, files that mix Windows and Unix line endings, and path fields written inline, like executor: { resource: x }. Those keep warning, and they keep the version from being bumped, so you can fix them by hand.

Limit

A v0.1 bundle never recorded which source supported which claim, so --migrate can move the citation list but cannot add footnotes.

For Claude Code plugin users

The plugin was renamed from okf to okf-skills, and the marketplace moved to ekar-is. The old name was the same as the official OKF plugin's, which made it look like the official one. To move an existing install, remove the old marketplace and install again:

/plugin marketplace remove scaccogatto
/plugin marketplace add ekar-is/okf-skills
/plugin install okf-skills@ekar-is

Commands change from /okf:okf to /okf-skills:okf, and likewise for validate, visualize and backfill.

The root keys got an x- prefix

The keys that configure the Stop hook moved to the prefix that the spec reserves for extensions:

Old keyNew key
upkeep: enforcedx-okf-skills-upkeep: enforced
recursive: truex-okf-skills-recursive: true

The old keys still work, and the validator warns about them. --migrate renames them for you.

Warning

Collaborators running okf-skills 0.12 or older read only the old keys. After you rename them, their hook stops enforcing until they update the plugin.
