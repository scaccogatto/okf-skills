Getting started

Pick the path that matches how you work. Each one ends the same way: check the bundle, then look at it.

Path 1By hand, any editor, no tools Path 2With an AI coding agent Path 3In CI, no agent

Path 1: by hand

Make a folder. Put a Markdown file in it with a type at the top. That is a bundle. Everything below is optional and can come later.

A few habits help as the bundle grows:

  • One file per thing you would explain to a new colleague.
  • Add an index.md at the root with okf_version: "0.3" and a one-line description of what the bundle covers.
  • Link concepts to each other where a reader would want to jump.
  • Record who wrote a concept in generated, and who checked it in verified, when you know.

OKF in plain words has examples of each part. You can stop here: nothing in this project is required to write or read OKF.

Check it by hand

The validator is a single Python script. It needs uv and Python 3.11 or newer.

git clone https://github.com/ekar-is/okf-skills
uv run okf-skills/skills/validate/scripts/okf_validate.py my-bundle

Errors mean the bundle breaks a conformance rule. Warnings are spec guidance, and are fine to leave for later. Without uv, pip install pyyaml and run the script with python3.

See it in the browser

uv run okf-skills/skills/visualize/scripts/okf_visualize.py my-bundle -o viz.html

Open viz.html in a browser. It is one file you can share. The live demo is what it looks like.

Path 2: with an AI coding agent

The skills teach an agent to write, update and read bundles from the spec. We test them in Claude Code.

Claude Code plugin

The plugin installs everything: the four skills, the subagents the backfill skill needs, the optional Stop hook and the MCP server.

/plugin marketplace add ekar-is/okf-skills
/plugin install okf-skills@ekar-is

Then ask in plain words ("document the invoice service in OKF"), or call the skill directly:

/okf-skills:okf produce .okf

The skills are /okf-skills:okf (write, update and read bundles), /okf-skills:validate, /okf-skills:visualize and /okf-skills:backfill. The default bundle location is .okf/, which is our convention, not the spec's. The skills accept any other path. The Stop hook only looks at .okf/.

Agent skills via skills.sh

npx skills add ekar-is/okf-skills

This installs the skill folders only, without the plugin's subagents, hook or MCP server, so the backfill skill does not work from this install.

Limit

We have tested the skills in Claude Code only. Other agents that support the Agent Skills format may load them, but we have not tried them, and the skill text is written with Claude Code in mind. If you run them elsewhere, an issue telling us what happened is welcome.

Check it with the agent

/okf-skills:validate .okf

See it with the agent

/okf-skills:visualize .okf

Path 3: in CI

The GitHub Action runs the validator on every push. It needs no agent, no account and no secrets.

Errors always fail the step. strict: "true" also fails on warnings. max-warnings: "5" is a middle ground for a bundle you are still cleaning up. The step exposes the validator's JSON report as the report output. @v1 follows the latest release while the project is before 1.0. Pin a release tag to freeze it.

Check it, outside GitHub

Any other CI can run the scripts directly from a checkout of okf-skills:

uv run okf-skills/skills/validate/scripts/okf_validate.py docs/knowledge --strict
uv run okf-skills/skills/validate/scripts/okf_validate.py docs/knowledge --json

The exit code is non-zero when the bundle fails. --json prints a machine-readable report.

See it

Render the graph as a build artifact or publish it with your docs:

uv run okf-skills/skills/visualize/scripts/okf_visualize.py docs/knowledge -o viz.html --title "Finance knowledge"

That is how this site's live demos are built: the storefront, the data catalog and this repo's own bundle.
