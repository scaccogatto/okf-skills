Knowledge as plain files

The Open Knowledge Format (OKF) is a way to write down what you know about your data, systems and processes, so that both people and AI agents can read it.

In the spec's words, the format is "a directory of Markdown files with YAML frontmatter". There is no schema registry, no central authority and no required tool. If you can open a text file, you can read it. If you can share a folder or a git repository, you can share it. The specification is short, Apache-2.0 licensed, and developed in the open at open-knowledge-format/open-knowledge-format. It is at version 0.3.

Each file is one concept: a table, a metric, a policy, a service, a runbook, anything worth explaining. A short block of metadata at the top says what kind of thing it is. The rest is ordinary Markdown. Here is a complete, valid concept:

You don't need us to use OKF

A bundle is a folder of text files. Any editor works, and the example above is fully conformant as it is. okf-skills is an independent community project, maintained by ekar.is. It is not the official OKF tooling and is not affiliated with the authors of the spec.

The OKF project ships its own agent skills, okf-generate and okf-consume. Start there if you are building a data catalog from existing sources, or answering questions with attested computations. Those are the cases the spec's own samples cover.

What okf-skills adds

We built okf-skills for teams that keep a bundle next to their code and want it to stay current as the code changes. It has a few parts:

  • A validator that checks a bundle against the conformance rules of the spec, and tells you which rule a finding comes from.
  • A visualizer that turns a bundle into a single HTML page with an interactive graph.
  • Agent skills for writing, updating and reading bundles, plus a skill that rebuilds a bundle from a repository's history.
  • An optional hook that reminds the agent to update the bundle before it finishes a task, a read-only MCP server, and a GitHub Action.

The validator, the visualizer, the Action and the MCP server work on any OKF bundle, from any domain. The upkeep features (the backfill skill and the hook) assume a git repository and Claude Code. The toolkit lists what each part assumes.

Quickstart

You need git, uv and Python 3.11 or newer. No account or sign-up.

The first command gets the scripts. The second creates a small starter bundle in my-bundle/. The third checks it. Then edit the files, add your own concepts, and run the check again. To see the result as a graph:

uv run okf-skills/skills/visualize/scripts/okf_visualize.py my-bundle -o viz.html

If you use Claude Code or another AI coding agent, Getting started shows the plugin and skill installs.
