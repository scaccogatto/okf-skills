QUESTION: Q4
Edit skills/validate/scripts/okf_validate.py. To add a new soft (warning-level) check, write a check_* function (or extend an existing one, e.g. check_concept, check_trust, check_lifecycle, check_sources) that calls report.warn(rel, "message") — this appends to Report.warnings, never Report.errors.
Error vs. warning is decided purely by which Report method the check calls: report.err(...) marks a hard §11 failure — missing/invalid frontmatter or missing type — and makes the bundle non-conformant (conformant = not r.errors). report.warn(...) is soft guidance and never affects conformant; it only fails the run if --strict (0 warnings allowed) or --max-warnings N is exceeded — otherwise warnings are just reported. Per the file's own header comment, only rules 1 and 2 (parseable YAML frontmatter, non-empty type) are hard errors; everything else the spec treats as soft, so a new check should almost always call report.warn.
