QUESTION: Q3
The repo ships two coexisting layouts from one source tree: the plugin manifest files make it a Claude Code plugin, while skills/<name>/SKILL.md makes it skills.sh-installable. Each skill bundles its Python script under its own directory (e.g. skills/validate/scripts/okf_validate.py), and every invocation references it as "${CLAUDE_SKILL_DIR}/scripts/okf_validate.py" rather than a hardcoded or repo-relative path. The runtime sets CLAUDE_SKILL_DIR to the skill's own directory regardless of whether it was loaded as a plugin subdirectory or as a standalone skills.sh install, so the same relative lookup resolves correctly in both layouts. This is documented as an explicit ADR pair.
The constraint: scripts can never be referenced by absolute path or by a path relative to the repo root — every script must live inside its own skill's directory tree and be addressed only relative to CLAUDE_SKILL_DIR, with no assumption about where that directory sits. The one place this gets stretched is the okf skill, which reaches into a sibling via ${CLAUDE_SKILL_DIR}/../validate/scripts/okf_validate.py — still relative, but it assumes the validate skill is installed alongside at the same level.
