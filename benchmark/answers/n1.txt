There's no config table or schema driving severity — each check function calls either report.err(rel, msg) or report.warn(rel, msg) directly, and that call site is what decides error vs. warning. The convention baked into the code is: only the two §11 hard rules — missing/unparseable frontmatter and a missing/empty type field — are report.err(...); every other soft-guidance check (recommended fields, trust/lifecycle/sources shape, actor conventions, timestamps, cross-links, legacy v0.1 constructs) calls report.warn(...). To add a new soft check, write a function that inspects meta/body and calls report.warn(rel, "…"), then wire it into check_concept (or check_index/check_log) alongside the existing check_trust/check_lifecycle/check_sources calls. Note --strict/--max-warnings only affect the exit code, not the error-vs-warning classification itself.
