QUESTION: Q1
The repo has an explicit ADR documenting this: the plugin ships zero hooks by deliberate design ("Ship no hooks — soft-mode upkeep"). Rationale: always-on hooks that observe arbitrary Claude Code sessions are intrusive and would fail third-party marketplace safety review. Instead, automatic OKF consume/maintain behavior is opt-in — a user pastes the snippet from templates/CLAUDE-okf.md into their project's CLAUDE.md, which instructs Claude to consult the bundle before tasks and write knowledge back after changes, rather than the plugin auto-installing a hook that fires on every session. The tradeoff accepted: no surprise behavior and easy passage of marketplace safety gates, at the cost of upkeep only happening if that CLAUDE.md snippet is actually present. Corroborated by the plugin manifest, which has no hooks field, and by there being no hooks directory anywhere in the repo.
