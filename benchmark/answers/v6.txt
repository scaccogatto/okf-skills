QUESTION: Q6
The trust tier isn't stored anywhere — it's computed on the fly by the visualizer's client-side JS from the concept's verified frontmatter field, per OKF spec §5.3.
The pipeline: read_trust() reads the verified field from each concept's YAML frontmatter (a bare {by, at} mapping or a list of such mappings) and embeds it verbatim into the generated NODES JSON baked into the HTML output. The tier label is then derived in the browser by trustTier(n): no verified entries → unverified; verified present but no entry's by starts with human: → machine-confirmed; any verified entry's by starts with human: → human-reviewed.
The code comment states the rationale explicitly: "the trust tier is derived, never stored... The exact lowercase prefix is the whole key." This matches spec §5.3, which defines trust tiers as an advisory signal derived from verified, not a stored/authoritative field, and explicitly says a concept with no trust frontmatter must still be consumable — trust tiers are not access control, just a classification computed from the raw provenance data the concept file actually stores.
